# SURLHWA — Project Vision

Last Updated: 2026-08-11

---

## 1. 프로젝트 개요

**설화(雪花 / SURLHWA)**는 외딴 설원 속 바를 배경으로 하는
스토리 중심 바텐딩 게임이다.

플레이어는 바텐더가 되어 이곳을 찾아온 손님들의 이야기를 듣고,
그들의 감정과 상황을 이해한 뒤 어울리는 칵테일을 만들어 건넨다.

게임은 경영 시뮬레이션의 외형과 하루 단위 영업 구조를 일부 사용하지만,
높은 수익을 내거나 경제적 압박을 극복하는 것이 핵심 목적은 아니다.

설화의 중심은 다음 세 가지다.

- 손님의 이야기
- 칵테일을 통한 플레이어의 응답
- 손님이 떠난 뒤에도 남아 있는 기억

---

## 2. 프로젝트 핵심 문장

> 한 사람이 떠난 뒤에도  
> 그 사람이 남긴 이야기가 공간에 남아 있는 게임.

설화의 장기적인 플레이 보상은 단순한 숫자 상승이 아니다.

처음에는 비어 있던 바가
플레이어가 만났던 사람들의 이야기와 흔적으로 점점 채워진다.

칵테일 도감, 특별 손님의 흔적, 스태츄,
환경 변화와 재방문 이벤트 모두 이 핵심 경험을 강화해야 한다.

---

## 3. 게임의 우선순위

설화의 콘텐츠 우선순위는 다음과 같다.

Story / Emotion

> Character Interaction
>
> Bartending
>
> Collection / Memory
>
> Light Management

경영은 플레이 리듬을 만드는 프레임이다.

다음 요소를 게임의 핵심 압박으로 사용하지 않는다.

- 과도한 매출 최적화
- 세금
- 월세
- 파산
- 반복적인 자원 노가다
- 강한 경제적 스트레스

평판이나 하루 손님 수와 같은 수치는 사용할 수 있지만,
플레이어 경험을 KPI 중심으로 만들지 않는다.

---

## 4. 칵테일의 의미

설화에서 칵테일은 단순한 제작 아이템이 아니다.

칵테일은 플레이어가 손님의 감정에 답하는 하나의 언어다.

플레이어는 손님의 이야기를 듣고
그 사람이 지금 어떤 감정에 놓여 있는지 생각한다.

그리고 어떤 칵테일을 건넬 것인지 선택한다.

따라서 조주 시스템은 다음 구조를 지향한다.

Story
→ Interpretation
→ Cocktail Choice
→ Bartending
→ Character Response

조주 미니게임만 재미있고
캐릭터의 이야기와 분리되는 구조는 지양한다.

---

## 5. 세계관

바는 인적이 드문 설원 깊은 곳에 존재한다.

현실의 시간과 공간에서 조금 벗어난 장소이며,
서로 다른 시대와 작품에 존재하는 인물들이 이곳을 방문할 수 있다.

외부는 눈보라가 몰아치는 차갑고 고립된 공간이다.

반대로 바 내부는 따뜻한 조명과 나무 소재를 중심으로 구성한다.

이 대비가 설화의 기본적인 시각적·감정적 분위기를 만든다.

설화의 바는 단순한 영업 장소가 아니다.

지친 사람들이 잠시 머물렀다가
다시 자신의 이야기로 돌아가는 경계 공간에 가깝다.

---

## 6. 특별 손님의 주제 스펙트럼

특별 손님들은 각자 하나의 인간적인 감정 또는 주제를 담당한다.

| 주제 | 캐릭터     |
| ---- | ---------- |
| 낭만 | 어린왕자   |
| 사랑 | 춘향       |
| 이상 | 돈키호테   |
| 고뇌 | 햄릿       |
| 선택 | 파우스트   |
| 희생 | 심청       |
| 귀환 | 오디세우스 |

원작의 사건을 그대로 재현하는 것이 목적은 아니다.

원작의 인물과 상징을 기반으로,
설화가 다루고자 하는 감정과 인간적인 질문을 재해석한다.

각 캐릭터의 상세 ACT는 `04_CONTENT_ROADMAP.md`를 따른다.

---

## 7. 기억이 남는 공간

플레이가 진행될수록 바 내부에도 변화가 생겨야 한다.

특별 손님이 자신의 이야기를 끝내면
그 인물을 상징하는 흔적이 바에 남는다.

이를 통해 플레이어가 메뉴를 열어 진행도를 확인하지 않더라도

"내가 누구를 만났고 무엇을 경험했는가"

를 실제 공간을 보고 느낄 수 있어야 한다.

바 자체가 하나의 세이브 데이터이자 기억의 전시장이 되는 것이 목표다.

---

## 8. UI / UX 철학

설화의 UI는 가능한 한 다음 느낌을 유지한다.

- 기록
- 기억
- 밤의 여운
- 조용한 관찰
- 손으로 정리한 일지

다음과 같은 인상은 지양한다.

- 과도한 KPI Dashboard
- 모바일 게임식 수치 폭발
- 지나치게 밝고 게임적인 Popup
- 끊임없는 보상 알림
- Story보다 숫자가 먼저 보이는 UI

예:

"영업 결과"

보다는

"밤의 마감"

과 같은 표현을 선호한다.

---

## 9. 실패와 평가

플레이어에게 완벽한 조주를 강요하는 것이 목표는 아니다.

Perfect / Good / Fail과 같은 결과는 존재할 수 있지만,
실패가 단순한 벌점으로 끝나서는 안 된다.

가능하면 실패 역시

- 손님의 반응
- 대화의 변화
- 작은 평판 변화
- 이후 기억

등 이야기 안에서 의미를 가져야 한다.

---

## 10. 프로젝트 개발 원칙

새로운 기능을 추가하기 전에 다음 질문을 확인한다.

1. 이 기능이 손님의 이야기를 더 잘 전달하는가?
2. 칵테일과 이야기를 연결하는 데 도움이 되는가?
3. 플레이어의 경험이 게임 공간에 남는가?
4. 기존 콘텐츠를 깨뜨리지 않고 확장할 수 있는가?
5. 데이터 추가만으로 콘텐츠를 늘릴 수 있는가?
6. 시스템 자체가 목적이 되어 게임의 핵심 경험을 흐리고 있지는 않은가?

명확한 이유를 찾지 못한다면 기능 추가를 다시 검토한다.

---

## 11. 최종적으로 만들고 싶은 경험

설화가 최종적으로 목표로 하는 것은
시스템이 가장 많은 게임도,
가장 어려운 경영 게임도 아니다.

하루가 끝난 뒤 플레이어가

"오늘 몇 골드를 벌었지?"

보다

"오늘 그 손님은 무슨 이야기를 했었지?"

를 먼저 기억하는 게임을 목표로 한다.
