## 2. 플레이 흐름과 콘텐츠

- 총 네 밤, 손님 만남은 5 / 4 / 4 / 4회, 총 17회다.
- 새 게임, 이어하기, 밤 전환, 밤 마감, Demo Complete를 연결했다. 완료 저장으로 이어가도 5일차는 생기지 않는다.
- 첫날 종료 시 다음 날 목표 인원으로 표시되던 문제를 수정해 완료한 밤의 실제 목표를 사용한다.
- 선택된 생산 칵테일은 설야, 만월, 드라이 마티니, 네그로니, 맨해튼, 진 피즈다. 예비 칵테일 콘텐츠는 호환성을 위해 유지했다.
- Stir / Shake / Build / Float 네 방식을 실제 재료·액체·용기·준비 상태에 따라 판정한다.

## 3. 레시피 학습과 추천

레시피는 대화에서 재료, 양, 준비 순서와 방법을 접한 뒤 실제로 시도하여 발견한다. 날짜가 바뀌거나 재료가 공급됐다는 이유만으로 Known 처리하지 않는다. 필수 발견 실패는 같은 손님에게 재시도할 수 있고, 어린왕자 방문 실패 이후에도 필요한 만월을 배울 별도 회복 경로가 있다.

추천은 완성한 술의 정체를 먼저 인식한 뒤 요청과의 감정적 적합성을 평가한다. 정확한 술을 지목하는 요청과 감정적 추천을 분리했고, 조주 방식용 주문 템플릿이 숨은 정답을 지정하지 않도록 했다. 배운 레시피, 공급 재료, 사용 가능한 방식과 해당 만남을 함께 확인했다.

통합 경로에서 설야/맨해튼, 네그로니/맨해튼, 만월/진 피즈 등의 대안을 실제로 만들었다. 이는 각 요청의 맥락과 당시 지식·공급 조건에 따른 선택이며, 모든 만남에서 모든 술이 유효하다는 뜻은 아니다. 첫날 초반에는 단서를 모으는 중이므로 이미 아는 술을 내고 FIT가 실패할 수 있고, 이후 교육 만남에서 드라이 마티니를 발견한다.

## 4. 어린왕자 세 번의 방문

| 항목 | 최종 동작 |
|---|---|
| 방문 시점 | 2일차, 3일차, 4일차 |
| 열린 작별 | 세 방문 모두 요청을 만족하는 술 + 성공한 조주 + 필요한 준비 충족 |
| 조용한 작별 | 한 방문이라도 잘못된 술, 조주 실패, 필요한 준비 실패가 있으면 적용 |
| 첫 방문 | 만월 요청 |
| 두 번째 방문 | 대사에 따른 Warmth 요청; 배운 술과 공급 조건에 따라 설야/맨해튼 등 해석 가능 |
| 세 번째 방문 | Clarity 요청; 당시 가능한 배운 술로 응답 |
| 실패 이후 | 방문 실패를 이야기로 받아들이고 진행. 나중 성공이나 재학습으로 과거 실패를 지우지 않음 |
| 작별 대화 | 읽기 완료 후 퇴장; 이전 선택과 방문 기록 반영 |
| 스태츄 | 향후 지급 자격만 저장. 이번 데모에는 실제 지급·전시 연출 없음 |

요청에 맞는 술이라도 조주 실패면 성공으로 인정하지 않는다는 사용자 결정을 반영했다. 가능한 성공/실패 이력 8가지를 검증했고, 열린 작별과 조용한 작별을 네 밤 통합 경로에서도 확인했다.

## 6. UI와 수정된 문제

- 한글 글리프가 상자로 나오던 문제를 기존 Noto Sans KR 기반 TMP fallback으로 수정하고 폰트 라이선스를 포함했다.
- 알려진 레시피의 양을 ml 우선, oz 보조로 표시한다. 실제 레시피 양·변환 상수·안정 ID는 바꾸지 않았다.
- 긴 레시피 설명에 스크롤을 추가하고 지식 수준에 따른 정보 공개 규칙을 유지했다.
- 안내문 중복, 레시피 버튼과 제목 겹침, Guide 위에 조주 텍스트가 비치던 문제를 수정했다.
- 대화창과 다음/선택/조주 버튼을 분리하고 선택 경로의 기본 New Text 표시를 정리했다.
- Stir의 컵·스푼 크기와 중심을 조정하고 마우스 궤도가 실제 캔버스 안에 들어오는지 확인했다.
- Guide·설정창을 읽는 동안 Shake 음표 시간이 소모되던 문제를 수정했다.
- 서빙 직후 미니게임 프리팹이 사라질 때 AudioListener가 잠시 없어지던 문제를 수정했다. 관측한 정리 프레임마다 활성 리스너가 정확히 하나인지 검증했다.

## 7. 저장·구조 보존

기존 칵테일·레시피·재료 ID와 저장 관계를 유지했다. 지식과 공급, 실제 음료 인식과 요청 적합성, 플레이어가 만든 액체 상태와 정답 메타데이터를 별개 책임으로 보존했다. 새 게임은 진행·지식을 초기화하고 음량 설정은 유지한다.

이어하기는 저장된 밤·지식·주요 방문 기록을 복원한다. 대화의 정확한 중간 위치나 만들던 액체를 그대로 복원하는 퀵세이브는 지원하지 않는다. 기존/불완전한 방문 기록을 열린 작별로 추측하지 않는 처리를 포함했고, 파괴적 저장 마이그레이션은 하지 않았다.

리뷰 이미지는 실제 Canvas를 렌더링한 화면 검토 자료다. OS 입력, 실제 디스플레이 가독성, 사람이 듣는 소리의 품질을 대신 검증하지 않는다. Windows 실행 검증 역시 시작 동작만 확인했으며 전체 완주나 정상 종료 동작까지 확인한 것은 아니다.

이번 Unity 검증은 실행됐으므로 라이선스 차단을 이유로 런타임 PASS를 추정하지 않았다. 빌드 경고 1개는 선택적 Unity Pipeline 명령/핫 리로드 서버가 꺼져 있다는 내용으로, URP 렌더링 실패가 아니다.

## 11. 권장 사용자 플레이 순서

1. 새 게임으로 네 밤 전체를 실제 마우스·키보드로 진행한다.
2. 필수 레시피의 준비를 한 번 틀리고 같은 손님에게 다시 시도한다.
3. 추천 요청에서 배운 다른 술과 다른 조주 방식도 선택한다.
4. 어린왕자 세 번 성공의 열린 작별과 한 번 실패의 조용한 작별을 각각 확인한다.
5. Guide·소리 설정을 읽고 닫은 뒤 조주가 자연스럽게 재개되는지 확인한다.
6. 밤 종료 후 이어하기, 데모 완료 후 이어하기, 새 게임 초기화를 확인한다.
7. 1280×720·1920×1080에서 글자·스크롤·버튼을 보고 음악·효과음을 직접 들어본다.
8. 대사와 네 밤의 호흡, 캐릭터·칵테일 그림, 바의 분위기를 평가한다.

이 결과물은 사용자가 독립적으로 실행하고 평가할 수 있는 내부 검토용 데모다. 최종 완성 및 공개 여부는 사용자 승인으로 결정한다.
