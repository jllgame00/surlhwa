# ACT 1 production art source set

These are original **built-in ImageGen** source atlases and exact prompts for the
2026-10-25 ACT 1 art pass. They preserve the C1 camera/open snow-bar direction;
they are modular source assets, not an alternate scene layout.

- Characters.png: bartender four poses; Prince and two anonymous ordinary
  winter guests with standing, seated and two walking poses.
- Environment.png: shelves/bottles/glasses, lamps, stool source, counter life,
  empty memory niche, snow rocks/banks and distant evergreen silhouettes.
- Materials.png: countertop, floor, front cabinetry and rear wood surfaces.
- Shelves-generated.png: wide bottle/glass modules refined to fit the accepted
  shallow shelf height without squashing bottle silhouettes.
- The four `*-prompt.txt` files record the exact prompts. Character generation
  used the preserved owner Prince anchor and existing bartender as references.
- assets.json records source hashes, crop bounds, output sizes, palettes and all
  43 output hashes. Prepared-assets.png shows the normalized set, not a game capture.

Run `python Production/Tools/prepare_act1_art.py` from the repository root.
Normalization follows the existing repository pipeline: declared extraction,
nearest sampling, palette reduction and binary alpha for new source art.
Ten existing pixel tool assets are copied byte-for-byte; their historical source
provenance remains applicable. New artwork is never attributed to that older set.

Source checks: `python Production/Tools/verify_act1_art_source.py`.
Gallery: `python Production/Tools/package_act1_art_source.py`.
The extraction/check scripts require Pillow; audio synthesis requires NumPy.
`dotnet build Production/Tools/PresentationCompile/PresentationCompile.csproj`
is a limited fallback using installed Unity 6000.3.7f1 assemblies and existing
Library package caches. It compiles the C# source in one auxiliary assembly;
it does not establish a clean Unity import, asmdef boundaries, shaders or runtime.

Runtime candidates live in
`Production/Unity/Assets/Surlhwa/Act1Assets/ProductionArt/`.
Use Unity `Surlhwa/Apply ACT 1 production art to existing scene`, or batch method
`Surlhwa.Editor.CampaignProductionArtBuilder.UpgradeScene`, after import. The
upgrader refuses unsaved scenes and preserves C1 geometry/camera/anchors.
`UpgradeAndBuildPlayer` upgrades the existing ACT 1 scene and builds its Player.
Ordinary asset variations are visual only; they do not create guest identities.

The stool illustration is retained as source/reference; runtime seats use its
extracted leather surface on the existing geometry to preserve contact.
New visual materials/meshes and Act1Art.asset are generated by the upgrader.
No old C1/Slice PNG or GUID is replaced.

FootstepFeltWood.wav is separately authored original procedural audio through
`Production/Tools/author_act1_footstep.py`. It is not ImageGen output. Its old
comparison cue is preserved; matching RMS does not establish perceived loudness.

Status: production-baseline **candidate**, HUMAN_SIGNOFF_REQUIRED. Source assets
and static compilation do not establish in-game appearance. The current license
block and exact integration status are in
`Production/Validation/ACT1_ART_PASS_PLAN.md`; Gate 2 remains open. Existing art
provenance/distribution caveats are not erased by this source checkpoint.
